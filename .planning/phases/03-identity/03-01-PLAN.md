# Phase 3 Plan 03-01 — Users, session, api_key, bootstrap

**Goal:** Login yields an HttpOnly session cookie; api_key is shown once and accepted on `GET /v1/me`; empty DB without bootstrap env refuses start.

**Requirements:** AUTH-01, AUTH-02, AUTH-03

## Tracer

Empty dir + `GFS_TOPOLOGY=vps` without bootstrap → `EnsureAdmin` error. With bootstrap: POST `/login` sets `gfs_session`; wrong password 401; POST `/v1/api-keys` returns a key; `GET /v1/me` with `Authorization: Bearer` is 200.

## Tasks

1. **Schema** in `internal/store`: `users`, `sessions`, `api_keys` via `CREATE TABLE IF NOT EXISTS` on Open. Methods: count/create/lookup user, session, api_key. Parameterized SQL only.
2. **`internal/auth`**: bcrypt hash/compare + dummy hash; generate `gfs_` key; SHA-256; ExtractKey from X-API-Key / Bearer only (no query, no form).
3. **Bootstrap** `store.EnsureAdmin(ctx, username, password)`: empty table requires both env values (min password 8); else no-op. `cmd/gfs` calls it after Open; error → exit 1. Never slog the password.
4. **HTTP**: GET/POST `/login` (vanilla form); POST `/logout`; GET `/` session stub HTML; POST `/v1/api-keys`; GET `/v1/me`; POST `/v1/users` (admin). Cookie `gfs_session` HttpOnly SameSite=Lax; Secure if `GFS_COOKIE_SECURE`.
5. **Config**: read bootstrap + `GFS_COOKIE_SECURE`; do not fail closed in `LoadFromEnv` for bootstrap (DB decides).
6. **Tests**: fail closed empty DB; login 401; login cookie; me via Bearer; access log must not contain password or raw key. `make ci` + cover ≥ 60.

## Verify

- Wrong password 401; good password Set-Cookie
- api_key hashed in DB (raw key not stored)
- Empty users + no env → process would exit 1
- `make ci` green

## Out of scope

Upload/list, HeadBucket, audit table, default password
