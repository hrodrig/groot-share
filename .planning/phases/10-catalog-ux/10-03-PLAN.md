### T2 — Inline upload JS (XHR + progress + cancel + duplicate)

**Files**
- `internal/server/identity.go` — extend `homeTmpl`'s inline `<script>`

**Script behavior** (vanilla JS, no framework):

1. On `change`/`drop`: read `file.name` + `file.size`; render
   `name · {humanSize}` in `#inline-dz-text` (mono). If `file.size >
   MaxUpload`, mark an inline error "exceeds the {limit} limit", disable
   `#inline-send`, and do **not** send.
2. Enable `#inline-send` only when a valid file is selected.
3. On submit:
   - `var fd = new FormData(); fd.append("file", file);`
   - `var xhr = new XMLHttpRequest(); xhr.open("POST","/v1/archives");`
   - `xhr.setRequestHeader("Accept","application/json");`
   - `xhr.upload.onprogress` → set `#inline-progress.value = e.loaded /
     (e.total || file.size)`; show the progress bar.
   - `xhr.onload` → parse JSON:
     - 201 + `storage:"transit"` → amber "in transit — bucket copy pending".
     - 201 otherwise → green "Capture uploaded".
     - 409 → red "already uploaded (same content)" + "View in Captures" link.
     - 413 → red "exceeds the size limit".
     - else → red "upload failed".
   - `xhr.onerror`/`xhr.onabort` → red "upload cancelled/failed"; reset
     the dropzone when aborted.
   - After a 201, re-render the list by reloading `/` (preserve current
     query string) so the new archive appears at the top.
4. **Cancel**: `AbortController` is not wired directly to XHR in the same
   way as fetch — use `xhr.abort()` from the `#inline-cancel` button; show
   `#inline-cancel` only while a transfer is in flight.

Note: use `xhr.abort()` (the XHR-native cancel) rather than the
`AbortController` wrapper — `XMLHttpRequest` exposes `.abort()` directly;
`AbortController` integration is optional and not required here. CONTEXT
D-05's "AbortController" is implemented as the equivalent `xhr.abort()`.

**Verification:** script is a no-op without a selected file; does not throw
when `navigator.clipboard`/`FormData` are unavailable (guard where needed).
