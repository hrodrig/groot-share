## Tasks

### T1 — Store: audit filters + indexes

**Files**
- `internal/store/audit.go` — add `AuditFilter` + filtered count/list.
- `internal/store/schema.go` — add indexes on `audit(actor)`, `audit(action)`,
  `audit(created_at)`.

`AuditFilter`:

```go
type AuditFilter struct {
    Actor  string // case-insensitive substring, empty = all
    Action string // exact, empty = all
    Since  time.Time // zero = all
}
```

- `ListAuditFiltered(ctx, f AuditFilter, limit, offset int) ([]Audit, error)`
  builds a `WHERE` from the filter (dynamic `AND` clauses, parameterized),
  always `ORDER BY id DESC LIMIT ? OFFSET ?`.
- `CountAuditFiltered(ctx, f AuditFilter) (int, error)` — same WHERE, `COUNT(*)`.

Keep `ListAuditPage`/`CountAudit` as thin wrappers over the filtered variants
with `AuditFilter{}` so existing callers/tests stay green.

**Verification:** `go test ./internal/store/`.

### T2 — Server: activity + audit filters via query params

**Files**
- `internal/server/audit.go` — parse filter params; thread through both
  handlers; add the export handler.

Parse helpers (shared by HTML, JSON, export):

```go
func auditFilterFrom(r *http.Request) store.AuditFilter
```

Reads `actor` (trim), `action` (trim), `window` (`24h`/`7d`/`30d` → `Since =
time.Now().UTC().Add(-d)`); unknown window values ignored (all).

- `handleActivityGET`: use `CountAuditFiltered`/`ListAuditFiltered`; put
  `AuditFilter` + selected values into template data so the form re-renders
  the current selection.
- `handleListAudit`: same filter (JSON list is filtered too).

**Verification:** `go test ./internal/server/ -run Audit`.

### T3 — Server: admin activity export

**Files**
- `internal/server/audit.go` — `handleActivityExport`.
- `internal/server/server.go` — route `GET /v1/activity/export`.

`GET /v1/activity/export?format=csv|json&actor=&action=&window=`:
- **admin-only** (explicit `ac.User.Role == auth.RoleAdmin`, not just
  `PermAuditRead`).
- Honor the same `auditFilterFrom` filters; **no pagination** (all rows).
- `format` defaults to `json`; `?format=csv` → CSV with header
  `actor,action,object_id,object_key,remote_ip,created_at` (RFC3339).
- `Content-Disposition: attachment; filename="activity.<ext>"`.

Reuse `auditJSON` for the JSON path. CSV quote via a small helper (escape
`"` → `""`, wrap fields containing `,`/`"`/newline).

**Verification:** curl-level test via `httptest` in audit_test.go.

### T5 — UI: typed-name confirm dialog

**Files**
- `internal/server/identity.go` — the `confirm-dialog` script (homeTmpl) AND
  `settings.go` — its own `confirm-dialog` script.

Change the shared modal JS to support a typed input:

- `data-confirm` stays as the prompt.
- `data-confirm-require="<value>"` sets the exact value to type.
- The dialog injects an `<input>` (mono) with a hint "Type {value} to
  confirm"; the OK button is `disabled` until `input.value === value`.
- On `close` with `returnValue === 'ok'` and a match, submit the pending form.
- When `data-confirm-require` is absent, keep the plain OK behavior (no input).

Add `data-confirm-require` to the destructive forms:
- archive delete (row + card): value = `.Key`
- api-key revoke (settings): value = `.Prefix`
- user remove / deactivate (admin users page): value = username
- share-link revoke (10-07 will use it too; not yet — no UI page exists yet)

The dialog markup needs a mono input slot. Find the `data-confirm` script in
`identity.go` (homeTmpl) and `settings.go`; update both (or factor a shared
script constant if it is already shared — verify).

**Verification:** `go test`; manual: delete archive shows "Type <key> to
confirm", button disabled until exact match.
