# Plan 10-06 — Manifest peek → partial-capture badge — Plan

**Phase:** 10 (Operational catalog UX)
**Requirement:** UX-08

## Objective

On the Captures page (and `GET /v1/archives` HTML), annotate **local (vps)**
archive rows with a completeness badge derived from the groot
`extras/manifest.json` job counters — `Complete` / `N of M jobs failed` /
`Failed`. Fail closed: any non-groot or malformed archive is unmarked.

## Tasks

### T1 — `peekManifest` helper (`internal/server/manifest.go`)

- `func peekManifest(r io.Reader) (total, success, failed int, ok bool)`:
  - `gzip.NewReader(r)`; on error → `ok=false`.
  - `tar.NewReader(gz)`; loop `Next()`:
    - `*tar.Header.Name == "extras/manifest.json"` **or**
      `strings.HasSuffix(name, "/extras/manifest.json")` → read member.
    - read with `io.LimitReader(tr, 64<<10)`, `json.Unmarshal` into a
      minimal `struct { Jobs struct { Total, Success, Failed int } }`.
    - validate: `total >= 0`, `failed >= 0`, `failed <= total`. On failure or
      no match → `ok=false`.
  - Cap total scanned bytes (`io.LimitReader` on the tar reader isn't needed;
    `Next()` skips bodies anyway, but we hard-stop after the manifest member).
- Pure stdlib (`compress/gzip`, `archive/tar`, `encoding/json`, `io`, `strings`).
  No groot import.

### T2 — wire into list rendering (`identity.go` / `archives.go`)

- Add a `Completeness` field (or a small struct) to the per-row view model used
  by `homeTmpl` (and `handleListArchives` JSON? no — HTML only; JSON contract
  untouched to avoid a SPEC §4 change).
- For each local archive in the list, open `BlobPath(id)` and call
  `peekManifest`. Fail-closed (missing file / unreadable → unmarked). Do this
  **only** for `Storage == "local"` / the non-bucket path; skip for `s3` and
  `transit`.
- Badge object carries: `Label string` (`Complete` / `N of M jobs failed` /
  `Failed`) and a `Tone` (`ok` / `warn` / `err`) for the CSS class.

### T3 — render badge (`identity.go` + `html.go`)

- In the list row (and the ≤ 719px card), render a small pill next to the key
  when the badge is present, absent otherwise. Reuse token classes
  (`--ok`/`--warn`/`--err`).
- Add a `.completeness-badge` CSS rule (small, muted, screen-reader text for
  the label).

### T4 — tests (`manifest_test.go` + dashboard assertions)

- Unit `TestPeekManifest`: build in-memory `.tar.gz` fixtures with
  `gzip.Writer` + `tar.Writer`:
  - manifest member `extras/manifest.json` with `jobs {3,2,1}` → `(3,2,1,true)`.
  - all-failed `jobs {1,0,1}` → `(1,0,1,true)`.
  - `jobs {}` (empty) / `failed > total` / malformed JSON / missing member →
    `ok=false`.
  - non-gzip bytes → `ok=false`.
  - member named `foo/extras/manifest.json` (suffix form) → matched.
- Integration: `TestHomeCompletenessBadge` — ingest a real groot-shaped
  archive through the store, GET `/`, assert the badge text renders; a
  non-groot archive renders no badge.
