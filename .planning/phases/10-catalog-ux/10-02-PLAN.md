# Plan 10-02 — Captures facets (cluster chips + search + time window + empty states)

**Phase:** 10 — Operational catalog UX

above the table with cluster chips (counts), search (substring of
filename), time-window chips (24h/7d/30d/all), and source/storage pills

clear-filters escape).

## Tasks

### T1 — `Filter` struct + `parseFilter`

**Files**
- `internal/server/filter.go` — new
- `internal/server/filter_test.go` — new

**`Filter` struct** (the request-scoped filter)
```go
type Filter struct {
    Cluster string  // exact match on cluster slug (empty = no filter)
    Query   string  // substring, case-insensitive
    Window  string  // "24h" | "7d" | "30d" | "" (= all)
    Source  string  // "http" | "s3" | "sftp" | "" (= no filter)
    Storage string  // "local" | "s3" | "transit" | "" (= no filter)
}
```

Helpers:
- `parseFilter(r *http.Request) Filter` — read query params, trim, allowlist
  Window values, drop invalid params silently.
- `func (f Filter) IsZero() bool` — true when no filter is set.
- `func (f Filter) WindowSince(now time.Time) (time.Time, bool)` — returns
  `(since, true)` for 24h/7d/30d, `(_, false)` for all.

**Tests**
- Empty query → all-zero Filter
- Invalid window → treated as "all"
- Trim whitespace; case-insensitive source/storage
- Multiple query params, only the canonical ones are read
- `WindowSince` math: 24h is exactly 24 hours ago, 7d is 7 days, etc.

**Verification:** gofmt, vet, test green.

### T2 — `Store.ListArchivesFiltered`

**Files**
- `internal/store/filter.go` — new
- `internal/store/filter_test.go` — new

**API**
```go
func (s *Store) ListArchivesFiltered(ctx context.Context, f Filter) ([]Archive, error)
```

The filter struct is **the server-side filter struct** (imported from the
server package? — no, the server-side Filter must be in `internal/store`
to avoid import cycles, so we put it in `internal/store/filter.go` too).

Actually the cleanest split: define the canonical filter struct in
`internal/store` (since SQL queries live there), and the server-side
`parseFilter` translates the HTTP request to that struct.

```go
// internal/store/filter.go
package store

import "time"

type Filter struct {
    Cluster   string
    Query     string
    Since     time.Time  // zero = no window
    Source    string
    Storage   string
}

func (s *Store) ListArchivesFiltered(ctx context.Context, f Filter) ([]Archive, error)
```

**SQL builder** (in-memory filter for VPS + S3 happens in Go, see T3)
Build a query with placeholders:
- `WHERE 1=1`
- if `f.Cluster != ""`: `AND key LIKE ?` (we don't store cluster as a
  column; we use the parser against `key` or pre-compute and store as a
  derived column in the result. The simplest is to post-filter in Go
  using the parser, which keeps SQL simple and works the same on
  SQLite + S3.)
- if `f.Query != ""`: `AND LOWER(key) LIKE ?` with `%query%`
- if `!f.Since.IsZero()`: `AND created_at >= ?`
- if `f.Source != ""`: `AND source = ?`
- if `f.Storage != ""`: `AND storage = ?`

`ORDER BY created_at DESC` (already the default).

`Cluster` is **post-filtered in Go** using `ParseClusterSlug` (consistent
with how the summary strip counts clusters from the unfiltered list).
This means a `?cluster=foo` query pulls the full SQL result and discards
non-matching rows; for an incident-evidence locker with hundreds of
archives this is fine. We document this in the comment.

**Tests** (real SQLite, seeded):
- Empty filter → same as `ListArchives`
- `?cluster=prod-eks-1` → only archives with that cluster slug
- `?q=2026-08-21` → only archives with that substring in `key`
- `?window=24h` (Since=now-24h) → only archives newer than that
- Combine `cluster + window + q` → all three filters apply (AND)
- Source/storage filters work

**Verification:** gofmt, vet, test green.

### T3 — Wire filter into `handleHome` + cluster chips from full list

**Files**
- `internal/server/archives.go` — extend `handleHome`
- `internal/server/catalog.go` — refactor `listItems` to accept an
  optional filter (or add a new `listItemsFiltered` that wraps both the
  bucket cache and the SQLite path)

**Flow**
1. `parseFilter(r)` → `Filter`
2. Fetch the **full** list (for cluster counts) — `s.listItems(ctx)`
3. Compute `Summary` (count, bytes, cluster count) from the full list
4. Fetch the **filtered** list — `s.Store.ListArchivesFiltered(ctx, store-filter)` for SQLite, or apply the same filter in Go after the bucket listing for vps-s3
5. Apply pagination + sort to the filtered list
6. Render the cluster chips from the **full** list (with per-cluster counts)
7. Render the facet bar (active state per filter)
8. Render the table with the filtered list

**Cluster chips data** (new field in data map)
```go
type clusterChip struct {
    Slug  string
    Count int
}
data["ClusterChips"] = []clusterChip{...} // sorted by count desc
```

The list of chips comes from a `clusterChips(items []Archive) []clusterChip`
helper that uses `ParseClusterSlug` to group, counts, and sorts.

**VPS + S3 path:** `s.listItems(ctx)` already returns the bucket
listing. We apply the filter in Go via a small `applyFilter(items, filter)`
helper that mirrors the SQL logic in T2. This is not the most efficient
but is correct; the bucket cache (5s TTL) keeps the cost low.

**Refactor note:** The existing `listItems` and `listItemsBucket` stay
unchanged; we add `listItemsFiltered(ctx, filter)` that wraps them. The
unfiltered list is still needed for the cluster chip counts.

**Tests**
- Filter applied to SQLite archives
- Filter applied to vps-s3 bucket listing (in-memory filter)
- Cluster chips reflect the full list, not the filtered one
- Empty result set → "no match" empty state

**Verification:** gofmt, vet, test green.

### T4 — Filter bar UI (chips + search + window)

**Files**
- `internal/server/identity.go` — modify `homeTmpl` (insert facet bar)
- `internal/server/html.go` — add `.filter-bar`, `.chip`, `.search`,
  `.window`, `.more-filters` styles

**Render position:** between the per-user pin strip (or summary strip if
no pins) and the table. Hidden entirely when `Count == 0` (per D-09).

**HTML sketch** (vanilla, server-rendered)
```html
{{if gt .Summary.Count 0}}
<form class="filter-bar" method="get" action="/" id="captures-filter">
  <div class="filter-row filter-primary">
    <div class="filter-chips" role="group" aria-label="Clusters">
      <a class="chip{{if not .Filter.Cluster}} is-active{{end}}" href="?{{stripCluster .QueryString}}">All <span class="chip-count">{{.Summary.Count}}</span></a>
      {{range .ClusterChips}}
      <a class="chip{{if eq .Slug $.Filter.Cluster}} is-active{{end}}" href="?{{withCluster $.QueryString .Slug}}">{{.Slug}} <span class="chip-count">{{.Count}}</span></a>
      {{end}}
    </div>
    <label class="filter-search">
      <span class="visually-hidden">Search</span>
      <input type="search" name="q" value="{{.Filter.Query}}" placeholder="filename, since, message" maxlength="80">
    </label>
    <div class="filter-window" role="group" aria-label="Time window">
      <a class="chip chip-sm{{if eq .Filter.Window ""}} is-active{{end}}" href="?{{stripWindow .QueryString}}">All time</a>
      <a class="chip chip-sm{{if eq .Filter.Window "24h"}} is-active{{end}}" href="?{{withWindow .QueryString "24h"}}">24h</a>
      <a class="chip chip-sm{{if eq .Filter.Window "7d"}} is-active{{end}}" href="?{{withWindow .QueryString "7d"}}">7d</a>
      <a class="chip chip-sm{{if eq .Filter.Window "30d"}} is-active{{end}}" href="?{{withWindow .QueryString "30d"}}">30d</a>
    </div>
    <button class="btn btn-quiet btn-sm filter-apply" type="submit">Apply</button>
  </div>
</form>
{{end}}
```

The `{{withCluster}}`, `{{stripCluster}}`, `{{withWindow}}`,
`{{stripWindow}}` template helpers are small URL builders that
add/remove a single query param while preserving the others. The submit
button is rendered because the user pressing Enter in the search box
should not auto-submit (we don't want surprise reloads); the user
clicks Apply or presses Enter inside the search input.

A small client-side script on the search input submits the form on
Enter (`<input type="search">` already does this on most browsers;
`formnovalidate` is not needed since there are no other inputs to
validate). Skip for now — `<button type="submit">` + Enter is enough.

### T5 — Empty states (no archives yet vs no match)

**Files**
- `internal/server/identity.go` — extend `homeTmpl` empty branch

  case (a "clear filters" link)

**Logic** (in the template, branching on `len .Items` AND `Filter.IsZero`)
- `Count == 0 && Filter.IsZero()` → **"No archives yet"** + "Upload
  archive" link (only when CanUpload) — already shipped in 10-01.
- `Count == 0 && !Filter.IsZero()` → **"No matches"** + description
  ("No captures match the current filters.") + **"Clear filters"** link
  to `/`.
- `Count > 0 && len(Items) == 0` (post-pagination) → just an empty
  table; not a true empty state.

**Tests**
- 0 archives total → "No archives yet"
- 5 archives, 1 cluster, filter `?cluster=does-not-exist` → "No
  matches" with "Clear filters" link visible
