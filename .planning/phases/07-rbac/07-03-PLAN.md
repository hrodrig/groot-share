# Phase 7 Plan 07-03 — api_key lifecycle + admin UI

**Goal:** Users create scoped keys, list prefixes, revoke keys. Admin has vanilla HTML user management.

**Requirements:** AUTH-05 (complete)

**Depends on:** 07-02 merged

## Tracer

Uploader POST `/v1/api-keys` `{scope:"upload"}` → 201. Same with `{scope:"read"}` → 403. Admin can create `read` scope. GET `/v1/me/api-keys` lists keys without secrets. DELETE revokes. Admin opens `/admin/users`, creates user via form.

## Tasks

1. **api_key store:**
   - `ListAPIKeysByUser(ctx, userID)`
   - `DeleteAPIKey(ctx, id, userID)` — owner or admin
2. **HTTP:**
   - Extend `POST /v1/api-keys` — body `{scope:"upload"|"read"}`; enforce role limits
   - `GET /v1/me/api-keys` → `{items:[{id,prefix,scope,created_at}]}`
   - `DELETE /v1/me/api-keys/{id}`
3. **HTML `/admin/users`** (admin session):
   - Table: username, role, active, created
   - Form: create user (username, password, role)
   - POST actions: deactivate, change role (forms, not SPA)
4. **HTML `/settings`** (any session):
   - Change password form → PATCH `/v1/me`
   - List api keys + revoke buttons
   - Create api_key form with scope dropdown (if role allows)
5. **Nav** — admin sees link to Users in header bar.
6. **GNUmakefile** — `COVER_MIN=70`.
7. **CHANGELOG** — v0.2.0 section: RBAC, migration note admin→role.
8. **REQUIREMENTS** — mark AUTH-05 complete.
