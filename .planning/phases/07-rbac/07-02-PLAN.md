# Phase 7 Plan 07-02 — Users CRUD API + self-service

**Goal:** Admin manages users via JSON API. Any user changes own password. Last-admin invariant enforced.

**Requirements:** AUTH-05 (partial)

**Depends on:** 07-01 merged

## Tracer

Admin POST `/v1/users` `{username,password,role:"viewer"}`. GET `/v1/users` lists all. PATCH demote last admin → 409. Non-admin POST `/v1/users` → 403. User PATCH `/v1/me` `{password}` works; wrong old password optional (skip old-password check v0.2 — admin reset only via PATCH user).

## Tasks

1. **Store methods:**
   - `ListUsers(ctx)`
   - `UserByID(ctx, id)`
   - `UpdateUser(ctx, id, role?, active?)`
   - `SetPassword(ctx, id, hash)`
   - `CountAdmins(ctx)` — active admins only
2. **HTTP handlers** (all `users:manage` unless noted):
   - `GET /v1/users` → `{items:[{id,username,role,active,created_at}]}`
   - `GET /v1/users/{id}`
   - `PATCH /v1/users/{id}` body `{role?, active?, password?}`
   - `DELETE /v1/users/{id}` → soft deactivate (`active=0`) preferred
   - `PATCH /v1/me` body `{password}` — any authed session
3. **Extend `POST /v1/users`** — accept `role` field; default `uploader`; validate enum.
4. **Last-admin guard** — helper `guardLastAdmin(ctx, userID, newRole, newActive)`.
5. **Errors** — 403 not 401 for forbidden admin routes (B-4).
6. **Audit** (optional but recommended): insert rows for user create/update/deactivate.
7. **Tests:** CRUD happy path; 403 non-admin; 409 last admin; inactive user cannot login.
